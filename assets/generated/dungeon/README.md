# Ashen Crypt materials

Original project artwork generated with the built-in OpenAI image generation tool on 2026-09-23. No commercial game artwork or downloaded third-party assets were used. Geometry, collision, banners and relief effigies are authored in `scripts/gameplay/ashen_crypt.gd`; flame sprites reuse the project's existing generated hearth artwork.

`crypt_materials.png` is a four-quadrant albedo atlas: upper left slate floor, upper right ashlar masonry, lower left carved gothic relief, lower right burgundy textile. `shaders/crypt_stone.gdshader` selects quadrants for dominant-axis stone projection and mapped relief/cloth. Mipmaps are enabled for distant stone while keeping nearest-neighbor filtering. Native alpha and source pixels are retained; no image editing or extraction was applied.

Generation prompt (built-in tool):

> Create a production game texture atlas 2048x2048 square, exactly four equal square quadrants with NO gutters NO text NO borders. Original gothic crypt material albedo, detailed HD-2D pixel textured realism, neutral flat diffuse lighting without directional shadows or perspective. Top-left quadrant: seamless repeating weathered charcoal slate large irregular rectangular floor slabs, grey brown rough stone, thin dark cracks, tiny worn pale edges and small chips, no grass. Top-right quadrant: seamless repeating ancient grey-brown ashlar wall masonry, small rectangular hand hewn blocks with mortar, restrained erosion. Bottom-left quadrant: sculpted gothic dark stone panel, centered recessed pointed-arch relief with geometric flower and decorative weathered stone trim, straight orthographic elevation. Bottom-right quadrant: old desaturated burgundy woven cloth texture with fraying, dark worn vertical folds, small stitched antique gold diamond insignia centered. Each quadrant fills its exact 1024x1024 region. Not a scene, not a presentation, no labels, no objects.

The generator returned a 1254×1254 image, used at native resolution. The separate dream-loop target, screenshots and visual verdicts are working evidence in ignored `.dream-loop/`, not runtime assets. Target prompt used an actual ruins screenshot as input:
